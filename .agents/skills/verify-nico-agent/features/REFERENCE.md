# Reference: fixtures and handles

What `seed` and `drift` put in a run, and the stable handles a recipe may use. Read the part a feature's recipe needs; `$C help` says how to call each.

## Fixtures

- `seed issues` caches, read now (fresh for a tick, 10 hours here): `verify/fixture#1` "Verify: a Ready issue" (Ready), `#2` "Verify: not labelled", `#3` "Verify: waits on #1" (unresolved Blocker `#1`, no PR), `#4` "Verify: assigned to someone else" (assignee `someone-else`), `#5` "Verify: a Research issue" (Ready, `research`, assigned to the user), `#6` "Verify: stacks on #9 PR" (Stackable on PR #109, head `agent/fixture-9`, which the fixture's origin does not have). The user is `verify-nico`. Its `open` list, every open issue as the Roadmap reads it, adds `#9` "Verify: a Blocker in review" (no label), `#30` "Verify: needs triage" (`needs-triage`, `bug`; assignees `verify-nico` and `someone-else`; a Markdown body; blocked by `#2`) and `#31` "Verify: needs info" (`needs-info`, blocked by `#30`). `seed issues chain` is the same with `#6` also blocked by `#8` "Verify: a Blocker stacked on #9", whose PR #108 (head `agent/fixture-8`) sits on `agent/fixture-9`: `#6` is Stackable on `agent/fixture-8`.
- `seed issues second` caches `verify/second#1` "Verify: waits on fixture #1" (unresolved Blocker `verify/fixture#1`, in another Repo), `#2` "Verify: waits on an outside issue" (unresolved Blocker `verify/outside#7` "Verify: an outside Blocker", in no Repo) and `#3` "Verify: waits on fixture #20 installed" (Blocker `verify/fixture#20` "Verify: a closed Blocker", closed at the read: Ready, until verify/fixture is in its Project with an `install` that has not run since).
- `seed dispatch <n> <kind>` records Dispatch `verify/fixture#<n>` "Verify: seeded Dispatch <n>". Use numbers above 6, not 20.
  - `pr`: every step done, in a worktree `worktrees/fixture-<n>` on `agent/fixture-<n>`, pushed to origin, holding `.evidence/<n>/proof.txt`, and its draft PR `https://github.com/verify/fixture/pull/<100+n>` open on the worktree's head in `prs.json`.
  - `asking`: as `pr` without a PR, its Implementer Asking "Should the fixture keep its README? (seeded by verify-nico-agent)".
  - `stacked`: as `pr`, but Stacked on `#9`'s open PR `https://github.com/verify/fixture/pull/109` (head `agent/fixture-9`, on `main`, also in `prs.json`): its Base and its PR's base are `agent/fixture-9`.
  - `restarted`: as `pr`, its Implementer restarted by the loop for two failing Verdicts an hour ago, so the next failing Verdict uses the restarts up.
  - `ruled`: as `pr`, a failing Verdict on its head an hour ago and one `verdict` restart since, its Evidence holding a `rulings.md` that dismisses the one Finding, and no push: with `seed reviewer <n>` (its Implementer idle) the next tick starts a Reviewer on the same head to rule on the Rulings.
- `seed run` records a Run open and blocked since now, as the loop does once herdr reports its agent blocked: `quality-scan` of verify/fixture (agent `quality-scan-fixture`), `morning` (agent `morning`), or `faux-nico <n>` (agent `faux-nico-fixture-<n>`) on the Asking of a Dispatch seeded `asking`. With herdr stubbed, no agent is ever seen ended.
- `seed morning <file>` puts `<file>`'s text in the config dir as `morning.md` (the agent itself is off in a run); `none` takes it away.
- `seed assign answers` makes the `gh` stub answer `gh issue edit <n> --repo <slug> --add-assignee @me` with success, so the Claim and "Assign to me" go through; `none` fails it again, as every other `gh` call fails.
- `seed rate-limit <file> [<bot-file>]` makes the `gh` stub answer `gh api rate_limit` with `<file>`'s JSON, and `ghbot`'s with `<bot-file>`'s (failing, as where ghbot is not installed, without one); `none` fails both again.
- `drift`:
  - `push <n>` commits to the seeded worktree, pushes it to origin and moves the PR's `head_sha`.
  - `stale` dates the cached read 2000-01-01, so the next `status` or `dispatch` asks GitHub.
  - `pause` writes GitHub paused for an hour.
  - `hang` makes every later `gh` call sleep till nico-agent kills it at its deadline (5 s in a run, which sets `NICO_AGENT_DEADLINE_SECS=5`); until cleanup.
  - `below merged|closed` makes PR #109 final; `final <n> merged|closed` makes seeded Dispatch `<n>`'s own PR (`#<100+n>`) final.

What launch makes: `stubs/` (`gh`, `ghbot`, `herdr`, `notify-send`, `curl`, `opencode2`, each appending its command line to `outside.log` and reaching nothing: `gh` exits 4 as with no login, `herdr` fails with code `verify_stub`, `notify-send` succeeds silently, `curl` fails as if offline, `opencode2` does nothing); `home/`, the scratch HOME with a `.gitconfig` naming `Verify Nico <verify-nico@example.com>` and a `config.toml` setting a free `port`, `tick_minutes = 600`, `bucket.path` to `bucket/` in the run dir and `morning.enabled = false`; `fixture/fixture` and `fixture/second`, clones of `verify/fixture` and `verify/second` whose GitHub origin URLs the scratch `.gitconfig` rewrites to bare repos on disk (any other github.com URL to a path that does not exist); serve started with `setsid`, ticking once at start with no Repo and then not for 10 hours, so every later tick is a `refresh` or the page's Refresh.

## Stable handles

CLI: the command words and flags (`--path`, `--json`, `--harness`, `--model`, `--effort`, `--sha`, `--findings`), the exit codes (`0` an answer, `1` a refusal as `{error, help}`, `2` a bad invocation), the JSON field names, and the routes in `GET` of an unknown path's `help`.

The Board (`/`), by ARIA role and name:

- `navigation "Projects"` in the rail (`complementary`): a `link "<name>"` per Project (a Repo with none is its own, named by its slug), the shown one `[current=page]`; `--click "link=<name>"` picks one. Under 720px the rail is hidden and `combobox "Project"`, first in `main` after `list "Needs you"`, has an `option` per Project instead (a Repo's Settings has one of the same name, later; `--select` takes the first): `--width 390 --select "Project=<name>"`.
- `list "Needs you"`: what needs you and has no node, each a `status` with `button "Dismiss <its head>"`, under `button "Hide notices"` (`"Show <n> notices"` once folded); absent when there is none. In the header, `heading "<project>"` (desk only), `button "Refresh"` and, in the Map view, `button "Repos"` (`[expanded]` while open). A node that needs you shows `Needs you` and its name ends `needs you`.
- In the rail: `group "Theme"` (`button "Light"`, `"Dark"`, `"System"`) and `group "GitHub rate limits" with `button "GitHub rate limits: <N>% of the tightest budget used"` (or `"GitHub paused until HH:MM"`), opening `heading "GitHub rate limits"` and a `heading "You · gh"` / `"Bot · ghbot"` per identity, each with `term` `REST` and `GraphQL`.
- A Project's `region "Repos"`, shown once `--click "button=Repos"` opens it, beside the map where the inspector goes: `region "<project>"` of its defaults (`region "Room"`, `"Switches"`, `"Settings"`) unless it is a Repo's own; then a `region "<slug>"` per Repo holding, in order, `region "Dispatch"`, `"Readiness"`, `"Room"`, `"Switches"`, `"Settings"`, `"Install"`, each folded to a `group` reading its head and what is set (`Dispatch 3 to dispatch`, `Readiness 2 of 7 pass`, `Room 3 · 0 in flight`, `Switches 4 of 9 on`, `Settings Implementer claude`, `Install None`) until `--click "region=<Section>"` opens it (a failing check or a refusal opens it by itself); then `button "Remove <slug>…"`; `region "Add a Repo"` at its foot. A `--click` takes the first match, the Project's defaults before any Repo's: use `--within "region=<slug>"`.
- Opened sections: `region "Room"` has `spinbutton "Room"`; `region "Switches"` a `switch` per switch (`Dispatch`, `Faux-nico answers`, `Flip to ready`, `Gardening`, `Only issues assigned to me`, `Quality-scan`, `Restart`, `Review`, `Stack`); `region "Settings"` `group "Implementer"` and `group "Reviewer"` (`combobox "<Role> Harness"`, then `combobox` or, where the Harness lists none, `textbox` `"<Role> model"` and `"<Role> Effort"`), `textbox "Base"` and `combobox "Project"` (a Repo's only); `region "Install"` `textbox "Install command"`. Beside each setting: `text: from Project` or `text: default` while it is taken, else `text: set here` and its × `button "Use the default <Setting>"` (or `"Use the Project's <Setting>"`); for two seconds after a save, `status: Saved` in their place.
- `navigation "View"` with `link "Map"` and `link "Roadmap"`. The Map view: `region "Map of <project>"`, a `button` per node named `#<n>[ <repo>], <title>, <Stage>[, agent <state>][, PR <n>[ draft]][, <line>][, needs you]`, then `group "Zoom"` (`button "Zoom out"`, `"Zoom in"`, `"Fit"`) and, while it holds a merged issue, `button "Hide merged"`. A node opens `region "<title>"`, the inspector, with `button "Close"`; the Roadmap view: see [roadmap](./roadmap.md).
- `region "Add a Repo"` with `textbox "Repo"`, `textbox "Its clone"`, `combobox "Its Project"`, `button "Add"`: in `region "Repos"`, and in `region "No Repo yet"` while there is none.
